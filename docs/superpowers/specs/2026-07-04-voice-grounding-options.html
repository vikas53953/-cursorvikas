Voice grounding · 6-panel brainstorm · 2026-07-04

Six ways to stop the AI improvising — pick one, mix them, or take it to Fable.

A panel of six specialists attacked one question: how to make voice answers faithful to what you asked and honest when it doesn't know — generally, with no per-case rules. None of these say "switch vs VLAN." Every one is a single contract over the real inventory.

Bug 1 — wrong / invented target"switch 99" silently became "VLAN 99 on sw1."
Bug 2 — fumbled the phrasing"version?" → answered IP, then hostname, then version.

The 6 options

O1

Inventory Lock: resolve, then run

Top pick
The AI literally can't run a command on a device until it's confirmed real. No real match → it can only ask, or say it doesn't exist.

Every action is forced into two steps: first check the name against the live catalog (found / ambiguous / not-found); the command tool then refuses anything but a confirmed real ID. Silent substitution becomes structurally impossible — not a rule, a wall. Kills Bug 1 as a whole category.

Trade-off: changes the tool definitions + a re-check on run. Doesn't fix mishearing the word itself.
effort Llatency lowstacks: O3·O5·O6·O4
O3

Engine-written answers

Top pick
For a fact question, the engine writes the exact sentence to say ("The version on sw1 is 17.9"); the AI just voices it — never digs through raw output.

The engine already knows you asked for "version," so it pulls that one value and hands over a ready line. The AI may not add any fact that isn't in it. If the device doesn't exist, there's no value to fill — so the only honest sentence is "I don't have that." Kills Bug 2.

Trade-off: can sound templated without a few natural lead-ins; broad questions need a summary mode.
effort Mno latencystacks: O1·O2·O5·O6
O6

Two-beat: speak now, confirm later

Top pick
An instant "let me check that on sw1…" keeps the talking-orb alive, then the real grounded fact once the engine returns. Speech starts immediately; only the fact waits.

The hedge commits to zero facts, so it can't be wrong, and it buys the ~second the engine needs. This directly fixes what killed the earlier attempt — that version blocked all speech until the engine finished, breaking the orb sync.

Trade-off: the hedge must stay genuinely non-committal; a truly slow device still means a slightly longer pause (slower-but-true).
effort Lno latencyenables O1·O3·O5
O5

Confidence ladder + honest "no"

The resolver says how sure it is → answer directly / ask "sw1 or sw12?" / say "there's no switch 99." Never silently defaults to sw1.

One three-rung policy, driven only by "how confident" and "how many matches" — same for a missing switch, an ambiguous "core router," or a shared interface. Also pins the last device so "what's its uptime?" can't drift. Mostly falls out of O1 for free.

Trade-off: thresholds need one-time tuning so it doesn't over-confirm the obvious and annoy you.
effort Mlatency mediumrides on O1
O4

Silent second-checker

The AI answers at full speed; a quiet check runs alongside — if the device or any number it's about to say doesn't match reality, cancel and correct before you hear it.

Two universal checks: the question is independently re-resolved and compared to what the AI actually queried; and every number spoken must literally appear in the real output. It's the only layer that catches a made-up fact on an otherwise-correct device. A background safety net.

Trade-off: corrects after the fact, so a real error means a brief "actually—" hiccup; needs number-normalizing ("nine one one" vs "9.1.1").
effort Mlatency lowsafety net
O2

Pre-flight fact sheet

The instant it hears you, look up every named thing and hand it a truth note ("switch 99: NOT FOUND; sw1: real") before it starts reasoning.

A generic scan pulls out entity-shaped mentions and checks each against the catalog, then injects the verdicts plus one blanket instruction: report NOT FOUND as not found. Same operation for any noun. Lighter to build than the lock.

Trade-off: it's advisory, not a wall — a determined improviser can still ignore it, so it's best paired with O1 or O4.
effort Mlatency lowpairs with O1·O4

The panel's recommendation

Not one option — a combination, built in order

The two failures are two different bugs, so the fix layers cleanly. All of it reuses the Phase 1 engine you already have, and every piece is one general contract over the live catalog — no per-case rules anywhere.
