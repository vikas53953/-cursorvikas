Enterprise architecture · 2026-07-04

A real NetOps copilot, built for the whole estate.

Ask any network question in plain language. NetJarvis finds the real devices, runs the real read-only command on them, and answers with real output — by voice or text. No fabricated data. No config changes. Ever.

Why it must scale

The target is Bank of America scale

The four Cisco sandbox switches are just what's reachable today. The architecture is designed for the real estate — tens of thousands of devices across four domains — so nothing is hardcoded to a handful of boxes.

The core idea

Two planes: look it up, then act on it

This mirrors how the enterprise actually works — you find a device in the CMDB, then SSH to it through the jump host to run a command. Discovery and action are kept separate and pluggable.

Plane 1 · which devices

Inventory / Scope

Search the CMDB (source of truth) for a bounded device set. Reference only — never a path to reach a device.

  • InventoryProvider · search / get
  • today: Catalyst Center
  • later: NetBox / ServiceNow
Plane 2 · run it

Execution

Run the read-only command directly on each real device's CLI, via a pluggable executor.

  • SSH · jump host → device
  • Catalyst Center · Command Runner
  • read-only, per platform

CMDB Inventory only

The catalog says which devices exist and how to reach them. You look things up in it; you never tunnel through it.

SSH Jump-host execution

Switches, firewalls, proxies and load balancers all have CLIs — one execution model (SSH via bastion), not four vendor APIs.

Plug Add a network, not a rewrite

New backend = register a source behind the same interfaces. Firewall / proxy / LB domains sit as empty slots until reachable — never faked.

Safety at scale

Nothing ever runs against the whole estate

A question is resolved to a bounded set first; execution is capped and concurrency-limited. These are the proposed defaults — sanity-check them against real ops.

25
Interactive cap
Above this many matched devices, summarize the count and require explicit confirmation before running.
500
Hard ceiling
Above this, refuse outright and ask the engineer to narrow the scope. No accidental 10,000-device fan-outs.
10
Max concurrency
At most this many simultaneous sessions; the rest queue. Per-device timeout returns partial results honestly.

Honest by construction

What's real today, what comes later

Everything built now is validated against the one real backend we can reach. Domains without a reachable source stay empty — never simulated.

How we get there

Four phases, each shippable

Every phase is validated on the sandbox before the next. Phase 1 becomes the first detailed implementation plan.

1

Foundation Next up

Source registry + domain model; InventoryProvider & Executor interfaces; Catalyst Center inventory+executor; SshExecutor proven on an SSH sandbox; Query Layer with scope + caps; remove the fake simulator; honest-unreachable; inventory-driven resolver; both pipelines call the Query Layer. Frontend: reachability badge, dead-code cleanup, topology rendering.

2

Scale hardening Later

Search / pagination / caching for large inventories; concurrency and cap behavior validated with synthetic scale; multi-platform read-only allowlists fleshed out.

3

Multi-domain readiness Later

Firewall / proxy / LB domain scaffolding, plus a pluggable InventoryProvider for a real CMDB (NetBox / ServiceNow) behind the interface — ready for real sources.

4

Enterprise connect Needs real backends

Real BofA CMDB + jump host + management systems; RBAC / user auth; deployment.
